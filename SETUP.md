# Setup & Session Handoff

This file gets a **fresh session** (a new machine, or a new agent with no memory) up
and running on MathHead, and hands off the ongoing roadmap work cleanly. The repo is
self-documenting by design — the durable handoff files below are the source of truth,
so continuity never depends on any one session's context.

## Quick start (fresh machine)

```bash
# 1. Clone (add https://<TOKEN>@github.com/... if the repo is private)
git clone https://github.com/tanzercakir-commits/MathHead && cd MathHead

# 2. Install the package + dev tools (z3, sympy, mcp, pytest, hypothesis, python-sat, ...).
#    mpmath ships with sympy — no extra numeric dependency. No networkx (graph
#    algorithms are pure stdlib by design). `[dev]` includes python-sat so the J3
#    high-performance-solver tests run; the runtime backend is the optional `[solvers]`
#    extra (the engine works without it — solve_cnf falls back / walls honestly).
pip install -e ".[dev]" --break-system-packages
# Exact tested backend set (reproducibility, ADR-0031):  pip install -e ".[dev,solvers]" -c constraints.txt

# 3. Verify everything is green
python -m pytest -q

# 4. Try the engine
python -m mathhead.cli --help
python -m mathhead.cli verify-eq "(x**2-1)/(x-1)" "x+1"   # domain-trap demo
```

The MCP server (how an AI actually uses the engine) starts with:

```bash
mathhead-server        # stdio transport (FastMCP)
```

## Read these first (the handoff files)

Newest status is always at the **top** of `Progress.md`. A new session reads, in order:

1. `Progress.md` — append-only log of what was done, when, why (newest on top).
2. `Todo.md` — what to do right now + the roadmap checklist.
3. `ROADMAP.md` — the staged milestones (`[x]` done, `[ ]` open) and honest walls.
4. `PRINCIPLES.md` — the non-negotiables (determinism, honesty, test-gating).
5. `DECISIONS.md` — the ADR log (why each design choice was made; ADR-0001…).
6. `docs/mcp-api.md` + `docs/api-reference.md` — the tool surface (the latter is
   auto-generated by `scripts/gen_api_reference.py` and enforced by a test).

## Continuing the roadmap (the working agreement)

**ROADMAP COMPLETE — all tracks A–K are done** (v1.0.0, API frozen; the engine exposes
**168 MCP tools** with the full test suite green — see `Progress.md` for the live count).
The tracks below are kept for historical context; remaining work is **productization**
(PyPI/release/tutorials — on the user, see `RELEASING.md`):

- **H — Logic & Proof Depth:** induction proofs (Z3 can't do this natively — needs
  special handling), SMT theories (arrays, bit-vectors, strings), deeper proof
  generation, optional modal/temporal logic.
- **J — Frontier:** new reductions (Ramsey, Sudoku, N-queens, …), verifiable UNSAT
  certificates (DRAT/LRAT — needs the external `drat-trim`), high-performance solvers
  (CaDiCaL/Kissat — external binaries).
- **K — Holistic Performance & Hardening:** caching/incremental solving,
  fuzzing/coverage, observability, and the v1.0 freeze (do this LAST — it's cross-cutting).

Each increment follows the same discipline — do **not** break it:

1. **Test-gated:** write the feature *and* its tests; the full suite must be green.
2. **Commit + push** the increment.
3. **Update the docs:** `Progress.md` (new entry on top), `Todo.md`, `ROADMAP.md`,
   `docs/mcp-api.md`, and regenerate `docs/api-reference.md`.
4. **Honest walls:** where something can't be done (or needs an external tool that
   isn't installed), say so plainly — never fabricate a result to look complete.

Guiding priorities: **correctness + determinism > speed**; the repo language stays
**English**; every tool returns the shared contract (`status`, `reason_code`,
`explanation`, `meta.elapsed_ms`).

**External-tool phases (J):** before claiming `drat-trim` / `CaDiCaL` / `Kissat`
support, check whether the binary can actually be installed in the environment. If it
can't, mark that phase as an honest wall in `ROADMAP.md` rather than shipping a stub.

## What is NOT in the repo (and must be re-provided)

- **A GitHub push token.** Commits push over HTTPS; the token is deliberately kept out
  of version control. In a fresh session, provide it and configure a credential helper
  (or embed it once in the clone URL). Without it, work stays local — still safe,
  because every increment is committed, just not pushed.

# MH-054 run-audit v1 to v2 migration

## Status

This migration activates `MH-C-AUDITED-RUN-002`,
`MH-C-RUN-AUDIT-REPLAY-002`, and `MH-C-RUN-AUDIT-STORE-002`. The accepted v1
contracts and their frozen reports remain immutable historical evidence.

## Reason

The v1 bundle retained each portfolio worker-result identity but did not retain
the canonical preimage needed to recompute that identity during logical replay.
An internally reidentified portfolio result could therefore preserve a
consistent outer content closure without giving replay the missing inner
evidence needed for an independent comparison.

V2 adds one closed worker-observation object for every visited producer and
checker. Each observation binds the deterministic request identity and the
complete portable preimage of the portfolio worker-result identity. Replay
reconstructs the request from the accepted plan, execution binding, governed
artifacts, and parent-ledger position, then checks the result, Evidence,
Certificate, decision, transition, and ledger links independently.

## Compatibility boundary

- V1 schemas, accepted contracts, and frozen reports are preserved unchanged.
- V2 parsers and the durable store accept only v2 bundles as current success.
- A v1 run record is historical input; it is never reinterpreted or relabelled
  as a v2-complete run.
- A current v2 bundle must be regenerated by executing the original accepted
  semantic inputs under the v2 audited-run contract. Migration does not copy or
  upgrade mathematical authority.
- Logical reports continue to exclude runtime worker observations and parent
  ledgers, so identical semantic inputs and outcomes retain portable report
  bytes even when effect observations differ.
